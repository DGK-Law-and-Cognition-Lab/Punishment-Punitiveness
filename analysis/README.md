# Analysis

This directory contains all analysis code for *The Dark Side of Punishment*. The pipeline is split into two language stacks — Python for the NLP feature extraction, R for the statistical analyses that consume those features and join them with the Study 1 quantitative measures.

## Pipeline Order

The Python NLP pipeline runs first and produces `data/processed/punishment_212_nlp_features.csv`. The R analyses then read that file along with `data/processed/punishment_212_cleaned_data.csv`.

```
data/processed/punishment_212_cleaned_data.csv  ────┐
                                                    ├──► R analyses (01–03)
analysis/python/01–03 ──► …_nlp_features.csv  ──────┘
```

## Files

### `python/`

Three notebooks correspond to the three NLP phases. Each is self-contained and can be run independently if the previous notebook's outputs are available.

| Notebook | What It Does |
|----------|--------------|
| `01_preprocessing_and_dictionaries.ipynb` | Text cleaning, VADER sentiment, Empath category scores, hand-built dictionary classifier (5 prosocial + 5 dark themes) |
| `02_classification.ipynb` | DeBERTa-v3-large zero-shot classification (8 labels), Claude Haiku 4.5 forced-choice and multi-label classification, 40-sentence ground-truth validation |
| `03_embeddings_and_similarity.ipynb` | Sentence embeddings via BGE-large (BAAI), voyage-3-large (Voyage AI), and Sentence-MPNet; cosine similarity to 5 prototype sets × 7 themes; BERTopic topic modeling; UMAP visualization |

**Requirements:**
- Python ≥ 3.10
- GPU recommended (notebook 2 will fall back to CPU but is much slower)
- API keys: Anthropic (for `02`) and Voyage AI (for `03`); set as environment variables `ANTHROPIC_API_KEY` and `VOYAGE_API_KEY`

### `r/`

Three R Markdown files cover the statistical pipeline, each producing a self-contained HTML report.

| Notebook | What It Does |
|----------|--------------|
| `01_main_analysis.Rmd` | Reverse coding, composite construction, scale reliability, descriptives, H1 (FDR-corrected correlations), H2 (Steiger Z-test), H3 (intercorrelation matrix), demographic moderation (48 interaction tests), CFA |
| `02_nlp_integration.Rmd` | Merges NLP features with Study 1 scales; constructs the 99-cell facade matrix; runs the six-measure multiverse classifier verdict (cultural-default vs. individual-facade vs. sincerity); per-theme correlations; hierarchical regressions for sentencing and punitiveness; mixed-effects sensitivity |
| `03_supplementary_analyses.Rmd` | Tautology sensitivity at three stringency levels (Original, Conservative, Strictest); bootstrap BCa confidence intervals; parsimony scale item-level analysis; TOST equivalence testing; sentence-anchor t-tests vs. 25-year midpoint; vignette correlation stability; prototype sensitivity multiverse |

**Requirements:**
- R ≥ 4.0
- See top-level `README.md` for the full package list

### `output/`

Generated artifacts from running the pipeline. These are checked in for ease of reference but can be regenerated by running the notebooks.

- `tables/` — ~64 CSV files used for tables in the manuscript and supplement
- `figures/` — ~18 PNG files used in the manuscript and the GitHub Pages site

## Reproducibility

The notebooks are deterministic given fixed seeds. Each Python notebook seeds NumPy, PyTorch, and Python's `random`. Each R Markdown sets `set.seed(20240601)` for bootstrap and resampling routines.

Some operations are not bit-for-bit reproducible across hardware:
- **GPU non-determinism**: DeBERTa zero-shot output can vary by ~0.1% in probabilities across CUDA versions, but top-1 predictions are stable.
- **API-based classifiers**: Claude is stable for a given model snapshot but its output may drift across model versions. The notebook records the exact model identifier (`claude-haiku-4-5-20251001`) used for the manuscript run.
- **Voyage embeddings**: Stable for a given snapshot of `voyage-3-large`.

For exact replication, regenerated `nlp_features.csv` outputs should be checked against the version checked into `data/processed/`.
